# 代码审查清单

## 简介

这是一份全面的代码审查清单，帮助审查者系统地检查代码质量、功能正确性、安全性等方面。

## 功能性检查

### 需求符合性
- [ ] 代码是否实现了所有需求？
- [ ] 边界条件是否正确处理？
- [ ] 错误场景是否考虑周全？

### 逻辑正确性
- [ ] 算法逻辑是否正确？
- [ ] 条件判断是否准确？
- [ ] 循环终止条件是否合理？

## 代码质量

### 可读性
- [ ] 变量名是否有意义？
- [ ] 函数名是否清晰表达意图？
- [ ] 代码结构是否清晰？
- [ ] 是否有必要的注释？

### 可维护性
- [ ] 代码是否遵循 DRY 原则（Don't Repeat Yourself）？
- [ ] 函数长度是否合理（通常不超过 50 行）？
- [ ] 是否有过度复杂的嵌套？
- [ ] 魔法数字是否提取为常量？

### 性能
- [ ] 是否存在不必要的循环嵌套？
- [ ] 数据结构选择是否合理？
- [ ] 是否有内存泄漏风险？
- [ ] I/O 操作是否优化？

## 安全检查

### 输入验证
- [ ] 所有用户输入是否经过验证？
- [ ] SQL 查询是否使用参数化？
- [ ] 是否防止了注入攻击？

### 敏感信息
- [ ] 密码、密钥是否加密存储？
- [ ] 敏感日志是否脱敏？
- [ ] API 密钥是否硬编码？

### 权限控制
- [ ] 是否有适当的权限检查？
- [ ] 资源访问是否受限？

## 测试覆盖

### 单元测试
- [ ] 关键逻辑是否有单元测试？
- [ ] 测试用例是否覆盖边界条件？
- [ ] 测试是否可重复执行？

### 异常处理
- [ ] 是否捕获了所有可能的异常？
- [ ] 异常信息是否清晰有用？
- [ ] 是否有适当的降级策略？

## 文档

### 代码文档
- [ ] 公共 API 是否有文档字符串？
- [ ] 复杂逻辑是否有注释说明？
- [ ] 是否更新了相关文档？

### 变更说明
- [ ] Commit 信息是否清晰？
- [ ] 是否记录了重要的设计决策？

## 兼容性

### 向后兼容
- [ ] API 变更是否破坏了向后兼容性？
- [ ] 数据库迁移是否正确？

### 跨平台
- [ ] 是否考虑了不同操作系统？
- [ ] 文件路径是否使用了正确的分隔符？

## 资源管理

- [ ] 文件句柄是否正确关闭？
- [ ] 数据库连接是否及时释放？
- [ ] 是否使用了上下文管理器？

## 最佳实践

### Python 特定
- [ ] 是否使用了类型提示？
- [ ] 是否遵循 PEP 8 规范？
- [ ] 是否使用了合适的标准库？

### 依赖管理
- [ ] 新增依赖是否必要？
- [ ] 依赖版本是否明确？

## 审查技巧

1. **先看大局**：理解整体架构和设计思路
2. **逐行阅读**：仔细检查每一行代码
3. **运行测试**：确保所有测试通过
4. **提出建设性意见**：避免纯粹的批评
5. **学习交流**：代码审查也是学习的机会
